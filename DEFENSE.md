# DEFENSE — Завдання 3: Взаємодія (Sequence)

Намір і критерії (1–2 речення):
Спроєктувати взаємодію сервісів, репозиторіїв та аудіосховища для сценаріїв успішного відтворення (SC-01), таймауту джерела (SC-02) та автовідтворення з пропуском заблокованих треків (SC-05) у межах UC-02. Побудовано 3 окремі Sequence-діаграми в Mermaid, використано складні фрагменти (`alt`, `opt`, `loop`), смуги активації не розриваються, а методи мають сигнатури та типи повернення.

Топ-3 розбіжності (spec ↔ артефакт) + коміт-виправлення:
• SC-01 згенеровано як лінійний процес без умовного розгалуження: оновлено spec.md (додано AC-5) та виправлено діаграму через промпт з блоком `alt (isBlocked == false / true)`. Коміт: https://github.com/ranenneyoulikemore/music-app-er/commit/59a6b2bc9a5b3d136bf6a2b8a8b6643fe4155a0f
• У SC-02 використано фрагмент `alt` замість `opt` для таймауту: додано AC-5 в spec.md та виправлено на блок `opt` для затримки >= 5000 мс із поверненням `504 Gateway Timeout`. Коміт: https://github.com/ranenneyoulikemore/music-app-er/commit/c45d0af74941c70d3a2cc226689c378b4634f6e9
• AI згенерував ідентифікатори як `String` замість `UUID` та приписав дій Актора `User` тип `: Void`. Коміт: https://github.com/ranenneyoulikemore/music-app-er/commit/cb286428f654b2e173dc28c5f63047b8c2dfb91a

Ключове рішення — які альтернативи зважив і чому обрав цю (ADR):
За [ADR-0004](doc/adr/0004-playback-sequence-interaction.md) обрано централізовану перевірку чорних списків на бекенді (`AudioService` -> `BlockService`). Альтернативу з фільтрацією на UI-клієнті (`AppClient`) відхилено через ризик розсинхронізації кешу та можливість обходу блокувань, що гарантує єдину бізнес-логіку для всіх платформ і не витрачає ресурси `AudioStorageProvider` на заблокований контент.

Перевірка — узгодженість із попередньою моделлю (як перевірив):
Перевірила типи даних у сигнатурах викликів — усе `trackId`, `userId`, `playlistId` мають тип `UUID`, що точно відповідає PK/FK сутностей `TRACK`, `USER`, `PLAYLIST` з ERD. Послідовності кроків повністю відтворюють Gherkin-сценарії SC-01, SC-02, SC-05, а `AudioStorageProvider` виступає внутрішнім бекенд-учасником, що відповідає ADR-0003.
