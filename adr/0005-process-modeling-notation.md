# [ADR-0005] Вибір нотації та форми моделювання бізнес-процесу відтворення треку (UC-02)

- **Статус:** Прийнято (Accepted)
- **Дата:** 2026-11-08
- **Контекст:** Необхідно обрати єдину декларативну форму для деталізації сценарію UC-02 ("Відтворення треку"), яка об'єднує успішне відтворення (`SC-01`), таймаут зовнішнього сховища (`SC-02`) та пропуск заблокованого контенту (`SC-05`).

## Context and Problem Statement

Для виконання вимог потрібно описати один бізнес-процес однією точністю формою без змішування нотацій. Модель повинна візуалізувати розподіл ролей (пули / swimlanes), розгалуження логіки (if/else), паралельне виконання завдань (fork/join) та асинхронний обмін повідомленнями з обробкою відсутності відповіді (таймаут 5 секунд). 

Яку нотацію та інструмент обрати для опису бізнес-процесу, щоб забезпечити максимальну наочність при код-рев'ю на GitHub та узгодженість із попередніми моделями?

## Decision Drivers

- **Візуалізація та рендеринг (NFR/DoD):** Нативна підтримка відображення схеми прямо в Markdown-файлах репозиторію GitHub без додаткових плагінів чи сторонніх редакторів.
- **Розподіл відповідальності (Swimlanes):** Чітке розділення дій між актором та сервісами (`User`, `AppClient`, `AudioService`, `AudioStorageProvider`).
- **Підтримка паралелізму та подій:** Можливість явно показати Fork/Join (одночасний запит метаданих та аудіопотоку) та очікування асинхронної події (таймаут CDN).
- **Наскрізна узгодженість:** Повна відповідність учасників та повідомлень Sequence-діаграмам із Завдання 3.

## Considered Options

1. **BPMN 2.0 XML** — галузевий стандарт моделювання процесів з багатою семантикою.
2. **Mermaid stateDiagram-v2** — моделювання переходів між станами системи або окремої сутності.
3. **Activity-діаграма у синтаксисі Mermaid Flowchart** — графічний опис потоку робіт із розділенням на пули через `subgraph`.

## Decision Outcome

Обрали **Опцію 3 (Activity-діаграма у Mermaid Flowchart)**.

Процес змодельовано у вигляді Activity-діаграми в одному файлі `doc/diagrams/uc-02-process-activity.md` з використанням 4 пулів (`subgraph`), явними вузлами `Fork`/`Join`, локальним вузлом очікування події (`WaitEvent`) та аварійним завершенням (`Terminate End`).

### Consequences

- **Good:** Нативний графічний рендер у GitHub PR без необхідності відкривати сторонні XML/файли зображень.
- **Good:** Зручний розподіл ролей за допомогою `subgraph`, що 1:1 повторює учасників із Sequence-діаграм Завдання 3.
- **Good:** Чітке моделювання аварійного гілкування: при таймауті 5 с процес іде в `Terminate End`, запобігаючи дедлоку (вічному очікуванню) на вузлі `Join`.
- **Bad:** На відміну від BPMN 2.0 XML, синтаксис Mermaid Flowchart вимагає явного текстового позначення специфічних подій для забезпечення коректної семантики Activity-діаграми.
