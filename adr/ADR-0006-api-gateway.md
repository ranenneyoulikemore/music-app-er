# [ADR-0006] ApiGateway як єдина точка входу клієнта в бекенд

- **Статус:** Прийнято (Accepted)
- **Дата:** 2026-11-11
- **Контекст:** Побудова компонентної моделі (Завдання 5). Потрібно визначити, як `AppClient` звертається до сервісів (`AudioService`, `BlockService`, `PlaylistService`, `SearchService`), щоб не порушити ADR-0004 (перевірка блокувань на бекенді) та межу системи.

## Context and Problem Statement

Клієнт (iOS, Android, Web) має доступ до UC-01..13. Чи може `AppClient` викликати сервіси напряму, чи всі виклики мають проходити через єдиний шар `ApiGateway`, який перевіряє токен (`AuthService`) і маршрутизує запити?

## Decision Drivers

- **Безпека:** Єдине місце перевірки авторизації; клієнт не має прямого доступу до `BlockService`, репозиторіїв і БД (ADR-0004).
- **Чіткість межі системи:** Один публічний інтерфейс `IApi` для всіх клієнтів.
- **Узгодженість із Sequence (Завд. 3):** Виклик `AppClient -> AudioService` лишається логічно незмінним.
- **Продуктивність (NFR-01):** Додатковий хоп не повинен ламати p95 ≤ 2 с.

## Considered Options

1. **Прямі виклики сервісів з AppClient** — кожен сервіс виставляє власний публічний API, авторизацію перевіряє кожен сервіс окремо.
2. **Єдина точка входу ApiGateway** — `AppClient` залежить лише від `IApi`; `ApiGateway` перевіряє токен через `IAuth` і делегує запит у `IAudio`, `IBlock`, `IPlaylist`, `ISearch`.

## Decision Outcome

Обрали **Опцію 2**. `AppClient` має єдину залежність — `IApi`. `ApiGateway` не містить бізнес-логіки: лише перевірка токена та маршрутизація. У Sequence-діаграмах Завдання 3 він прозорий (зафіксовано в spec як припущення).

### Consequences

- **Good:** Єдина перевірка авторизації; клієнт не може обійти `BlockService` прямим запитом.
- **Good:** Межа системи чітка: назовні виставлено тільки `IApi` та `ICatalogImport`.
- **Good:** Нові клієнти підключаються без змін у сервісах.
- **Bad:** Додатковий мережевий хоп `AppClient` -> `ApiGateway` -> сервіс (враховується в бюджеті NFR-01).
- **Bad:** `ApiGateway` не показаний на Sequence-діаграмах Завдання 3; розбіжність пояснена в spec.

## Pros and Cons of the Options

### Опція 1: Прямі виклики сервісів (Відхилено)

- **Good:** Немає додаткового хопа.
- **Bad:** Авторизація дублюється в кожному сервісі.
- **Bad:** Клієнт залежить від внутрішньої структури сервісів.
- **Bad:** Ризик обходу перевірки блокувань (суперечить ADR-0004).

### Опція 2: ApiGateway (Прийнято)

- **Good:** Єдина точка авторизації та маршрутизації.
- **Good:** Клієнт ізольований від внутрішніх сервісів.
- **Bad:** Ще один компонент для підтримки.
